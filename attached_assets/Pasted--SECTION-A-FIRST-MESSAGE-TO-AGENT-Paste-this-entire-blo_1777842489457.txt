## What You Are Building

**ScholarForge Chess** — a browser-based classroom chess platform for high school chess clubs. It combines rules-correct chess gameplay with tactical training, student growth tracking, and teacher tools. It is deployed from a single link with no login required in Phase 1.

This is not a hobby project. It will be used in a real classroom with real students. Every technical decision must reflect that.

## The North Star Principle

> "Does this feature help a student understand WHY their thinking was wrong — or does it only tell them THAT it was wrong?"

## The Three Non-Negotiables

These are hard rules. They are not open for interpretation or "we'll add it later" decisions.

**1. chess.js is the rules engine from move one.**
No illegal moves can ever be made on this board. No temporary "we'll add validation later." chess.js drops in as a dependency in 5 minutes and handles all rules natively. A platform that allows illegal moves in a classroom loses its credibility permanently the first time a student slides a bishop through a piece in front of the class.

**2. The homepage (home.tsx) does not get touched.**
The existing homepage — Royal Blue hero, Playfair Display headline, owl logo, "Play Now" CTA — is the brand identity of Owls Chess Club. It stays exactly as-is throughout the entire Phase 1 build. Do not redesign it, do not refactor it, do not "improve" it.

**3. Every data structure in Phase 1 must support the full 5-phase roadmap.**
Do not build Phase 1-narrow data models that require refactoring in Phase 2. Specifically: the gameStore, studentStore, puzzle schema, and PGN metadata format must be shaped to accommodate Phase 2–5 requirements from day one. The full roadmap is in the blueprint below.

## The Full Product Vision — 5 Phases

### Phase 1 — Core Board + Rules + Interaction Foundation (BUILD NOW)
Deliver a stable, rules-correct, classroom-ready chess board with student identification, game recording, visual customization, and three lightweight teaching features.

### Phase 2 — Puzzle Engine + Tactical Skill Tracking
A spaced repetition puzzle system using the Lichess open puzzle database. Candidate move capture. Mistake taxonomy that classifies errors by cognitive type (vision / calculation / evaluation / knowledge gap / psychological) not just right/wrong.

### Phase 3 — Student Profiles + Adaptive Training
Full student performance profiles. Structured 4-step game review. Cross-game pattern detection. Claude API-generated coaching narratives per student.

### Phase 4 — Teacher Dashboard + Broadcast Tools
Teacher broadcast mode with live class heatmap showing which squares students click on a shared position. Teacher lesson authoring. Class-wide position challenges with timed submissions.

### Phase 5 — Advanced Systems + Club Management
Chess clock, Stockfish.js computer opponent, opening explorer, Chess960, user accounts, club Elo tracking, tournament brackets.

## Step 6 — Build the Chess Engine Wrapper

Create `src/engine/chessEngine.ts` — a typed wrapper around chess.js.

Must expose:
- `makeMove(from, to, promotion?)` → returns move result or null if illegal
- `getLegalMoves(square)` → returns array of legal destination squares
- `getBoardState()` → returns current FEN
- `getHistory()` → returns SAN move array
- `getFENHistory()` → returns FEN array (one per half-move — for O(1) rewind)
- `isCheck()`, `isCheckmate()`, `isStalemate()`, `isDraw()`
- `loadFEN(fen)` → sets position
- `getPGN(white, black, event?)` → returns formatted PGN string
- `reset()` → new game

## Step 14 — Three Phase 1 Teaching Features

### openingPrinciples.ts
Pure function. Takes SAN move history array. Returns violations array. Called after game ends, not during play.

Checks first 10 moves for:
- Same piece moved twice before all minor pieces developed
- Queen developed before move 6 with undeveloped pieces
- King uncastled after move 10 with open center

Returns: `{ moveIndex: number, violation: string, explanation: string }[]`

Display in game-end modal and review mode as inline notation annotations.

### thinkingTimer.ts
Records `Date.now()` delta between moves. Stored as `timesPerMove: number[]` in gameStore. No UI during play. Surfaced in review mode:
- Under 5000ms → orange indicator on move in notation panel
- Over 180000ms → blue indicator on move in notation panel

### Post-Game Annotation Fields
In game review mode, after game ends, for the 3 moves with longest think times:
- Three textarea questions per position:
  1. "What were you trying to do here?"
  2. "What were you worried about?"
  3. "Looking at it now, what do you think went wrong?"
- Student answers saved before any engine/principle analysis is shown
- Stored in GameRecord.annotations

interface Puzzle {
