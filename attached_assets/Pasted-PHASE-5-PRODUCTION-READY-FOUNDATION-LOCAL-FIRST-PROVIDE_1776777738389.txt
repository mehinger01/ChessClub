PHASE 5 — PRODUCTION-READY FOUNDATION (LOCAL-FIRST, PROVIDER-BASED, MIGRATION-SAFE)

---

1. PURPOSE

---

Phase 5 transforms the app into a stable, portable, role-based system that:

* Works in real school environments
* Supports Admin, Teacher, Student roles
* Persists and restores data reliably
* Can run fully local with no external calls
* Can run hosted for pilot use
* Can be migrated to school servers later
* Prepares for future multi-school productization
* Introduces theme and piece customization foundations

---

2. CORE ARCHITECTURE REQUIREMENTS (CRITICAL)

---

2.1 PROVIDER LAYER (MANDATORY)
All data access MUST go through provider/service layers.

NO direct calls to:

* Supabase
* localStorage
* file system
* external APIs

Instead use interfaces:

storageProvider:
saveStructuredData()
loadStructuredData()
exportData()
importData()

databaseProvider:
create()
read()
update()
delete()
query()

authProvider:
login()
logout()
createUser()
resetPassword()
requirePasswordReset()

fileProvider:
saveFile()
loadFile()
listFiles()

puzzleSourceProvider:
loadLibrary()
importLibrary()
validateLibrary()

RULE:
App logic must NEVER depend on a specific backend implementation.

---

## 2.2 LOCAL-FIRST REQUIREMENT (MANDATORY)

System must fully function with:

* local database
* local file storage
* no external API calls
* local puzzle library
* admin-controlled authentication/reset

This is required for school deployment.

---

## 2.3 DEPLOYMENT MODES (MANDATORY)

deploymentMode:
"hosted"
"school"
"restricted"

Behavior:

HOSTED:

* Supabase allowed
* Email reset allowed
* External calls allowed

SCHOOL:

* Local DB preferred
* Internal services only
* External calls disabled by default

RESTRICTED:

* NO external calls
* Local puzzle source only
* Admin-managed authentication only

All providers must respect deploymentMode.
